# ST-Zero 格式兼容层设计

> 版本：v0.1（草案）
> 日期：2026-08-30
> 目标：与 SillyTavern 社区资源格式 1:1 兼容，社区存量数据（Chub 数十万卡片）可直接导入
> 权威来源：SillyTavern 源码（参考/SillyTavern）、角色卡规范仓库（参考/character-card-spec-v2/v3）、ChungusHub 架构文档（参考/ChungusHub/architecture/sillytavern-interchange.md）

---

## 1. 兼容原则

1. **未知字段必须保留不销毁**（MUST NOT destroy）：所有格式的未知字段原样保留，导入→导出必须是固定点（往返不变量）
2. **字段名保持 SillyTavern 原样**：不重命名、不转换字段名
3. **解析器 fail-loud**：格式错误时明确报错，不静默吞掉
4. **识别 ≠ 导入**：能识别格式 ≠ 能完整导入，导入前做能力检查
5. **V3 只读兼容**：V3 规范仍在演进，导出默认 V2

## 2. 角色卡（Character Card）

### 2.1 格式识别

| 格式 | 检测方式 |
|---|---|
| V1 | 顶层无 `spec` 字段，有 `name`/`description` 等 V1 字段 |
| V2 | `spec === 'chara_card_v2'`，数据在 `data` 下 |
| V3 | `spec === 'chara_card_v3'`，数据在 `data` 下 |
| JSON 文件 | 文件内容直接是卡片对象 |
| PNG | tEXt chunk 中 `chara`（V2）或 `ccv3`（V3）key，值 = base64(utf-8 JSON) |
| CharX | ZIP 包，根目录有 `card.json`，资源用 `embeded://` URI |
| YAML | 解析为卡片对象 |

### 2.2 PNG tEXt chunk 读写

**读取**：
1. 解析 PNG 所有 chunk
2. 提取 tEXt chunk，查找 keyword 为 `ccv3` 的（V3），其次 `chara`（V2）
3. 值解码：base64 → utf-8 → JSON.parse
4. 两者并存时优先 `ccv3`

**写入**：
1. 删除已有 `chara`/`ccv3` chunk
2. 在 IEND chunk 前插入新的 `chara` tEXt chunk（base64 编码的 V2 JSON）
3. 可选同时写入 `ccv3` chunk（spec 改为 `chara_card_v3`）
4. 重新计算 CRC-32

**实现参考**：
- ST：`src/character-card-parser.js`、`src/png/`
- ChungusHub：`src/lib/services/pngText.ts`（buildTextChunk/insertTextChunk/readTextChunk + crc32.ts）
- 注意：ST 的 parse() 只支持 PNG，WebP 无标准（V1 规范明确不覆盖）

### 2.3 V2 字段定义

```ts
type TavernCardV2 = {
  spec: 'chara_card_v2'
  spec_version: '2.0'
  data: {
    name: string
    description: string
    personality: string
    scenario: string
    first_mes: string
    mes_example: string
    creator_notes: string          // 永不进入提示词
    system_prompt: string          // 空时回退用户全局设置
    post_history_instructions: string
    alternate_greetings: string[]
    character_book?: CharacterBook
    tags: string[]
    creator: string
    character_version: string
    extensions: Record<string, any>  // 未知 key 不得销毁
  }
}
```

**版本检测规则**：`spec === undefined` 为 V1；`spec === 'chara_card_v2'` 时读取 `data` 下字段

### 2.4 V3 新增字段

```ts
type CharacterCardV3 = TavernCardV2 & {
  spec: 'chara_card_v3'
  spec_version: '3.0'
  data: {
    // V2 全部字段 +
    assets?: Array<{ type: string; uri: string; name: string; ext: string }>
    nickname?: string              // 存在时 {{char}} 替换为该值
    creator_notes_multilingual?: Record<string, string>
    source?: string[]
    group_only_greetings: string[]
    creation_date?: number
    modification_date?: number
  }
}
```

- `assets` 未定义时默认 `[{type:'icon', uri:'ccdefault:', name:'main', ext:'png'}]`
- `uri` 可为 HTTP/HTTPS URL、base64 data URL、`embeded://path`（CHARX）、`ccdefault:`（指向 PNG 文件本身）
- 版本比较按浮点解析：>3.0 警告但必须能导入，<3.0 视为旧版本

### 2.5 CharacterBook（内嵌世界书）

```ts
type CharacterBook = {
  name?: string
  description?: string
  scan_depth?: number
  token_budget?: number
  recursive_scanning?: boolean
  extensions: Record<string, any>
  entries: Array<{
    keys: string[]
    content: string
    extensions: Record<string, any>
    enabled: boolean
    insertion_order: number
    case_sensitive?: boolean
    name?: string
    priority?: number
    id?: number
    comment?: string
    selective?: boolean
    secondary_keys?: string[]
    constant?: boolean
    position?: 'before_char' | 'after_char'
  }>
}
```

- `insertion_order`：数值越小插入越靠前；`priority`：预算超限时数值越小越先被丢弃
- `selective: true` 时需 `keys` 和 `secondary_keys` 各命中一个才触发
- 导入时：`character_book` 提取为独立世界书，同时保留与角色卡的关联

### 2.6 CharX（ZIP）格式

```
card.zip
├── card.json              # CharacterCardV3 对象（必须）
└── assets/
    └── {type}/            # icon/background/emotion/user_icon/other
        └── {images|audio|video|l2d|3d|ai|fonts|code|other}/
            └── 资源文件
```

- 资源通过 `embeded://path/to/asset.png` URI 访问（注意拼写是 `embeded` 不是 `embedded`，路径大小写敏感）
- zip 不应加密，文件名/路径仅用 ASCII

### 2.7 ST 私有字段（extensions 约定）

ST 在 `data.extensions` 下使用的标准字段（导入时保留，导出时原样带出）：
- `talkativeness`：数值，群聊话痨程度
- `fav`：布尔，收藏
- `world`：绑定的世界书文件名
- `depth_prompt`：`{ depth, prompt, role }` 角色深度提示
- `regex_scripts`：角色级正则脚本数组
- 外部工具约定：`pygmalion_id`、`github_repo`、`source_url`、`chub: {full_path}`、`risuai: {source}`、`sd_character_prompt`

## 3. 世界书（World Info / Lorebook）

### 3.1 文件结构

```json
{
  "name": "世界书名称",
  "entries": {
    "0": { "uid": 0, "key": ["关键词"], "content": "...", ... },
    "1": { "uid": 1, ... }
  },
  "extensions": {}
}
```

**关键：`entries` 是以 uid 为键的对象（不是数组）**，每个条目带 `uid` 字段

### 3.2 条目字段映射（内部 camelCase → 存储 snake_case）

| `keysecondary` | `secondary_keys` | `[]` | 次要关键词 |
| `comment` | `comment` | `''` | 条目标题/备注（不进入提示词） |
| `content` | `content` | `''` | 激活时插入的内容 |
| `constant` | `constant` | `false` | 常驻（无需关键词） |
| `vectorized` | `extensions.vectorized` | `false` | 向量存储匹配 |
| `selective` | `selective` | `true` | 选择性激活（需次要键） |
| `selectiveLogic` | `selectiveLogic` | `0` | 0=AND ANY, 1=AND ALL, 2=NOT ANY, 3=NOT ALL |
| `addMemo` | `extensions.add_memo` | `false` | 内容前自动加备注 |
| `order` | `insertion_order` | `100` | 插入顺序（大数靠后） |
| `position` | `extensions.position` | `0` | 0=before_char, 1=after_char, 2=ANTop, 3=ANBottom, 4=atDepth, 5=EMTop, 6=EMBottom, 7=outlet |
| `disable` | `enabled`（取反） | `false` | 禁用条目 |
| `ignoreBudget` | `extensions.ignore_budget` | `false` | 忽略 token 预算 |

| `matchPersonaDescription` | `extensions.match_persona_description` | `false` | 匹配 persona 描述 |

| `groupWeight` | `extensions.group_weight` | `100` | 组权重（随机选择概率） |
| `scanDepth` | `extensions.scan_depth` | `null` | 条目级扫描深度覆盖 |
| `caseSensitive` | `extensions.case_sensitive` | `null` | 条目级大小写敏感覆盖 |
| `matchWholeWords` | `extensions.match_whole_words` | `null` | 条目级整词匹配覆盖 |
| `useGroupScoring` | `extensions.use_group_scoring` | `null` | 组评分 |
| `automationId` | `extensions.automation_id` | `''` | 自动化 ID（与快捷回复联动） |
| `role` | `extensions.role` | `0` | 0=system, 1=user, 2=assistant |
| `sticky` | `extensions.sticky` | `null` | 激活后保持 N 条消息 |
| `cooldown` | `extensions.cooldown` | `null` | 冷却 N 条消息 |

## 4. 正则（Regex）脚本

### 4.1 脚本 JSON 结构

```json
{
  "id": "UUID",
  "scriptName": "脚本名",
  "findRegex": "/pattern/flags",
  "replaceString": "替换文本（支持 {{match}}、$1 捕获组）",
  "trimStrings": ["要修剪的字符串"],
  "placement": [1, 2],
  "disabled": false,
  "markdownOnly": false,
  "promptOnly": false,
  "runOnEdit": false,
  "substituteRegex": 0,
  "minDepth": null,
  "maxDepth": null
}
```

### 4.2 字段说明

| 字段 | 说明 |
|---|---|
| `id` | UUID（新脚本生成） |
| `scriptName` | 脚本名，slash command 触发时的定位标识 |
| `findRegex` | 查找正则，可含宏（`{{user}}` 等，取决于 substituteRegex） |
| `replaceString` | 替换文本；`{{match}}` 插入完整匹配，`$1`/`$2` 为捕获组 |
| `trimStrings` | 替换前从匹配中移除的字符串数组（多行按 `\n` 拆分） |
| `placement` | 数字数组：0=MD_DISPLAY（废弃）、1=USER_INPUT、2=AI_OUTPUT、3=SLASH_COMMAND、4=sendAs（遗留）、5=WORLD_INFO、6=REASONING |
| `disabled` | 禁用（禁用后 slash command 也无法触发） |
| `markdownOnly` | 仅影响显示（不写聊天文件） |
| `promptOnly` | 仅影响提示词（不写聊天文件） |
| `runOnEdit` | 编辑消息后也运行 |
| `substituteRegex` | 0=NONE（宏按字面）、1=RAW（宏原样替换）、2=ESCAPED（宏值正则转义） |
| `minDepth`/`maxDepth` | 影响的消息深度范围（0=最后一条；空/-1=不限） |

### 4.3 存储位置

- **global**：settings.json 的 `extension_settings.regex`
- **scoped**：角色卡 `data.extensions.regex_scripts`
- **preset**：AI 预设文件
- 导出：单个 `.json` 文件（`regex-{scriptName}.json`）

## 6. 聊天记录（JSONL）

### 6.1 文件结构

- 路径：`chats/{角色名}/{聊天名}.jsonl`（角色名 = avatar_url 去 `.png`）
- 群聊：`group chats/{id}.jsonl`
- **首行是 header**：`{ "chat_metadata": {}, "user_name": "unused", "character_name": "unused" }`
- 之后每行一条消息 JSON

### 6.2 消息对象

```ts
interface ChatMessage {
  name?: string
  mes?: string
  title?: string
  gen_started?: number
  gen_finished?: number
  send_date?: number
  is_user?: boolean
  is_system?: boolean
  force_avatar?: string
  original_avatar?: string
  swipes?: string[]
  swipe_info?: SwipeInfo[]
  swipe_id?: number
  extra?: ChatMessageExtra
}
```

`extra` 字段：`api`、`model`、`type`、`gen_id`、`bias`、`uses_system_ui`、`memory`、`display_text`、`reasoning_display_text`、`tool_invocations`、`title`、`isSmallSys`、`token_count`、`swipeable`、`overswipe_behavior`、`files`（附件数组）、`inline_image`、`media_display`、`media_index`、`media`、`[IGNORE_SYMBOL]`（排除出提示词）

### 6.3 校验规则

- 一行含 `name` 或 `character_name` 或 `chat_metadata` 即视为有效
- 备份命名：`chat_{name}_{timestamp}.jsonl`（非字母数字转下划线、小写）
