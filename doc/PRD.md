## 1. 产品概述

### 1.1 产品定位

ST-Zero 是一个从零构建的 AI 角色扮演 Web 应用（"类酒馆"项目），核心目标是：

1. **完全兼容 SillyTavern 社区生态**：角色卡（V1/V2/V3）、世界书、正则脚本、预设、聊天记录等可分享资源格式 1:1 兼容，用户从 Chub 等平台下载的资源可直接导入使用
2. **解决原版三大痛点**：
   - **UI 落后**：放弃 jQuery + 原生 JS，采用现代前端框架（Svelte 5），组件化、响应式、移动端友好
   - **运行臃肿**：模块化架构，按需加载，告别 11.5MB 前端 JS 和 202 个脚本文件
   - **计算全在前端**：世界书扫描、正则处理、prompt 构建、宏替换、token 预算管理全部迁移到服务端，浏览器只做渲染和交互
3. **多用户支持**：管理员账户可当作普通用户使用，只是比普通用户多一个管理员面板入口
4. **Docker 部署**：单容器 + 数据卷，开箱即用

### 1.2 目标用户

| 用户类型 | 描述 | 核心需求 |
|---|---|---|
| 自托管个人用户 | 单机部署，自己使用 | 开箱即用、资源导入、多后端接入 |
| 家庭/小团体 | 2-20 人共享一个实例 | 多用户、数据隔离、管理员管理 |
| 社区运营者 | 半开放社区 | 用户管理、注册控制、权限控制 |

### 1.3 非目标（MVP 不做）

- 不实现 STscript 完整兼容（后置）
- 不实现扩展/插件系统（后置）
- 不实现 RAG/向量检索（后置）
- 不实现 TTS/STT/生图（后置）
- 不做多租户（tenantId）设计

## 3. 功能需求

### 3.1 角色卡管理（P0）

- **导入**：PNG（tEXt chunk `chara`/`ccv3`）、JSON 文件、CharX（ZIP）、YAML；自动版本检测（V1/V2/V3）
- **导出**：PNG 内嵌 JSON（V2 格式，`chara` chunk）；可选导出 V3（`ccv3` chunk）
- **编辑**：全部 V2 字段（name/description/personality/scenario/first_mes/mes_example/creator_notes/system_prompt/post_history_instructions/alternate_greetings/tags/creator/character_version/extensions）
- **列表**：卡片网格/列表视图、搜索、标签过滤、收藏
- **未知字段保留**：导入导出时 `extensions` 及未知字段必须原样保留（MUST NOT destroy）

### 3.2 聊天（P0）

- 单聊：用户 ↔ 角色
- 流式输出（SSE）
- Swipe：备选回复切换（swipes 数组）
- 消息编辑、删除、重新生成
- 聊天记录自动保存（JSONL 格式，与 ST 兼容）
- 多聊天会话管理（每个角色可开多个聊天）

### 3.3 世界书（P0）

- 导入/导出（ST 格式 JSON）
- 条目管理：关键词、内容、插入顺序、位置、选择性、常量、概率、组、深度、角色、正则匹配
- 扫描：深度扫描、递归扫描、token 预算控制
- 角色卡内嵌世界书（character_book）导入时自动提取

### 3.4 正则（P0）

- 导入/导出（ST 格式 JSON）
- 全局正则（settings 级）+ 角色级正则（scoped，存角色卡 extensions）
- 作用位置：用户输入、AI 输出、世界书、斜杠命令
- 支持 `{{match}}`、`$1` 捕获组、trimStrings、minDepth/maxDepth、markdownOnly/promptOnly

### 3.5 AI 后端（P0）

- **OpenAI 兼容 API**：OpenAI、DeepSeek、GLM、通义、Ollama、vLLM、OpenRouter 等（统一抽象）
- **KoboldAI API**：KoboldCpp 本地推理
- 两种 prompt 结构：Chat Completion（消息数组）+ Text Completion（单字符串 + Instruct 模板）
- API key 服务端加密存储
- 采样参数：temperature、top_p、top_k、min_p、repetition_penalty 等

### 3.6 预设（P1）

- 采样器预设、指令预设（instruct）、上下文预设（context）
- 与 ST 格式兼容（可导入 ST 预设文件）

### 3.7 群聊（P1）

- 多角色群聊、talkativeness 概率发言、群成员管理

### 3.8 快捷回复（P1）

- 快捷回复组、按钮触发、自动化触发（executeOnUser/executeOnAi 等）

### 3.9 多用户系统（P0）

- **角色**：`user` | `admin`（admin 是 user 的超集，拥有全部权限）
- **认证**：JWT + bcrypt，登录/登出
- **注册策略**：默认仅管理员创建；可选开放注册（首个用户自动成为 admin）
- **单用户模式**：`ENABLE_ACCOUNTS=false` 时无需登录，内置默认管理员
- **数据隔离**：结构化数据按 user_id 隔离；文件数据按每用户目录隔离
- **管理面板**：同应用内 `/admin` 路由，侧边栏条件渲染入口（仅 admin 可见）
  - 用户列表/搜索
  - 创建用户（用户名/密码/角色）
  - 启用/禁用用户
  - 提升/降级角色
  - 删除用户（可选清除数据）
  - 站点设置（注册开关、默认角色）

### 3.10 部署（P0）

- Docker 单容器：`ghcr.io/0sour/st-zero:latest`
- 环境变量：`PORT`、`DATA_DIR`、`ENABLE_ACCOUNTS`、`ALLOW_REGISTRATION`、`JWT_SECRET`、`DEFAULT_USER_ROLE`
- 数据卷：`/app/data`
- 健康检查

## 4. 非功能需求

| 类别 | 需求 |
|---|---|
| 性能 | 前端首屏加载 < 2s（gzip）；世界书扫描 1000 条目 < 100ms（服务端）；流式输出首 token < 1s |
| 兼容性 | 角色卡/世界书/正则/预设/聊天 JSONL 五类格式与 ST 1:1 兼容；未知字段不销毁 |
| 安全 | 密码 bcrypt 哈希；JWT 签名；API key 加密存储；路径穿越防护；登录限流（5 次/分钟/IP） |
| 可维护性 | TypeScript 全栈；核心算法为纯函数（可单测）；模块化架构 |
| 可测试性 | 格式往返测试（导出→导入→导出 固定点）；核心算法单元测试 |
| 国际化 | i18n 架构预留（中文/英文起步） |
| 移动端 | 响应式布局，移动端可用 |

## 5. MVP 范围（MoSCoW）

### Must（P0，第一版必须）
- 角色卡导入导出（V1/V2/V3 + PNG tEXt + CharX）
- 单聊 + 流式输出 + swipe
- 世界书（扫描/递归/预算）
- 正则（global + scoped）
- OpenAI 兼容 + KoboldAI 后端
- 多用户 + 管理面板
- Docker 部署
- 聊天 JSONL 保存

### Should（P1，第二版）
- 预设（采样/指令/上下文）
- 群聊
- 快捷回复
- 聊天记录导入导出
- persona
- 开放注册 + 首个用户 admin

### Could（P2，后续）
- STscript 兼容
- RAG/向量检索
- TTS/STT
- 生图
- 翻译
- 扩展/插件系统

### Won't（明确不做）
- 多租户
- OAuth 第三方登录
- 独立管理端

## 6. 成功指标

- 从 Chub 下载的 Top 100 角色卡 100% 可导入且字段无损
- 世界书/正则资源导入成功率 ≥ 95%
- 前端 bundle 体积 ≤ 500KB（gzip）
- 服务端 prompt 构建耗时 ≤ 200ms
- 单容器 Docker 部署 ≤ 5 分钟

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| ST 格式细节遗漏导致兼容失败 | 高 | 以 ST 源码为格式权威；建立真实资源测试集；格式往返测试 |
| 计算后移改变行为 | 高 | 核心算法纯函数化，前后端共享同一实现；与 ST 行为对照测试 |
| V3 规范仍在演进 | 中 | V3 只读兼容，导出默认 V2 |
| 多用户数据迁移 | 中 | 单用户模式默认数据目录与多用户模式兼容（default-user） |
