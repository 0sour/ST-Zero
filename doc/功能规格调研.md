## 0. ST 通用 UI 模式（重写时的组件库基础）

### 0.1 控件类型统计（ST index.html 全量）

| 控件 | 数量 | 用途 |
|---|---|---|
| checkbox | 171 | 开关类设置 |
| number 输入 | 133 | 数值设置 |
| range 滑块 | 105 | 采样参数等连续值 |
| text 输入 | 62 | 短文本 |
| textarea | 36+ | 多行文本（描述/提示词） |
| file 选择 | 22 | 导入/上传 |
| radio | 17 | 互斥选项 |
| select 下拉 | 大量 | 枚举选择 |
| search | 8 | 搜索框 |

### 0.2 核心 UI 组件模式

| 模式 | 说明 | ST 实现 |
|---|---|---|
| **抽屉（drawer）** | 主导航：顶部图标按钮 + 侧滑面板，互斥打开 | `.drawer` > `.drawer-toggle` + `.drawer-content`，`closedDrawer/openDrawer` 类切换 |
| **折叠面板（inline-drawer）** | 面板内分组折叠 | `.inline-drawer-toggle`（标题+chevron）+ `.inline-drawer-content` |
| **弹窗（popup）** | 统一弹窗系统，5 种类型 | `callGenericPopup(content, POPUP_TYPE, inputValue, options)`；TEXT/CONFIRM/INPUT/DISPLAY/CROP |
| **滑块+数字联动** | 滑块与数字输入框成对，`data-for` 关联双向同步 | `.range-block` > `.range-block-title` + `.range-block-range-and-counter` |
| **右键菜单** | 手写实现，绝对定位 + 视口边界修正 | `#character_context_menu`，长按 2.5s 移动端触发 |
| **拖拽上传** | 全局拖拽 + 高亮 + drop 回调 | `DragAndDropHandler` 类 |
| **按钮类** | `menu_button`（通用）、`red_button`（危险）、`mes_button`（消息内）、`interactable`（可交互图标） | FontAwesome 图标 + class |
| **输入框类** | `text_pole`（统一输入样式）、`textarea_compact`（紧凑） | — |
| **checkbox 行** | `checkbox_label` > checkbox + small 文字 | — |
| **tab** | 简单 tab：按钮 `data-target-tab` + `.navTab` 面板 | admin 面板 |

### 0.3 设置保存机制

- **整包保存**：前端维护巨型设置对象（约 20 个模块），debounce 后整体 POST `/api/settings/save`，后端原子写 `settings.json` + 定时快照
- **ST-Zero 改进建议**：改为字段级 API（按模块保存），避免整包传输

## 2. 聊天功能

### 2.1 聊天界面布局

```
┌─────────────────────────────────────────────┐
│ 顶部栏（抽屉图标按钮组）                       │
├─────────────────────────────────────────────┤
│ 消息区 #chat（滚动）                          │
│   ┌─ 消息气泡 ──────────────────────────┐    │
│   │ 头像 名字 时间 token数               │    │
│   │ 正文（Markdown 渲染）                │    │
│   │ hover: 编辑/复制/更多按钮            │    │
│   │ swipe 左右箭头（最后一条）            │    │
│   └─────────────────────────────────────┘    │
├─────────────────────────────────────────────┤
│ 输入栏 #send_form                           │
│   [☰菜单] [textarea 输入] [停止][冒充][继续][发送] │
└─────────────────────────────────────────────┘
```

### 2.2 消息气泡

| 元素 | 说明 |
|---|---|
| 头像 | 角色/用户头像 |
| 消息序号 | #N |
| 生成计时 | 生成耗时 |
| token 数 | `${count}t` |
| 名字 + 时间戳 | title 带 API/model 信息 |
| 正文 | Markdown 渲染 + DOMPurify 消毒 |
| hover 按钮 | 编辑（铅笔）、书签（checkpoint）；展开菜单（省略号）：翻译/生图/朗读/隐藏/复制/swipe 历史/分支 |
| 编辑模式按钮组 | 确认/复制/加 reasoning/删除/上移/下移/取消 |

### 2.3 发送消息流程

1. 用户输入 → 点发送按钮或回车 → `sendTextareaMessage()`
2. 有文本则构造用户消息对象 → 推入 chat 数组 → 渲染 → 防抖保存
3. 组装 prompt（角色卡 → 世界书扫描 → 历史裁剪）→ 请求 AI 后端
4. **流式**：fetch + ReadableStream 解析 SSE（`\n\n` 分帧，`event:`/`data:` 字段）→ 逐 chunk 更新消息 DOM
5. 完成后保存最终消息（含 swipes/swipe_id/swipe_info 结构）

**ST-Zero 关键差异**：prompt 组装在**服务端**完成（ST 在前端），前端只发 `{content}` 到 `POST /api/chats/:id/messages`，服务端返回 SSE 流

### 2.4 Swipe（备选回复）

| 项 | 规格 |
|---|---|
| UI | 最后一条 AI 消息左右箭头按钮；键盘左右方向键；Swipe Picker 弹窗（列表预览 + 选中/删除/分支） |
| 逻辑 | 右箭头：下一个备选，到末尾则生成新备选（overswipe 行为可配置）；左箭头：回退 |
| 数据 | 消息对象内嵌 `swipe_id`/`swipes`/`swipe_info`，随聊天 JSONL 保存，无独立 API |
| ST-Zero 建议 | 保持 JSONL 内嵌结构（格式兼容），但生成新 swipe 走服务端 API |

### 2.5 消息编辑/删除/重新生成

| 操作 | UI 交互 | 后端 |
|---|---|---|
| 编辑 | 铅笔按钮 → 正文变 textarea + 编辑按钮组 → 确认 | 纯前端 + `chats/save` 落盘 |
| 删除 | 编辑模式删除按钮 / 删除模式（输入栏变 Delete/Cancel 条 + 消息左侧复选框，勾选后从该条起全部删除） | 纯前端 + 保存 |
| 重新生成 | 菜单 → 删最后一条 AI 消息 → 重新生成 | 走生成流程 |
| 移动 | 编辑模式上移/下移按钮 | 纯前端 + 保存 |

### 2.6 聊天会话管理

| 操作 | UI 交互 | 后端 API |
|---|---|---|
| 新建 | 菜单 → 确认弹窗（含"删除当前聊天"checkbox）→ 清空 + 注入 first_mes（alternate_greetings 作为 swipes） | 写回角色卡 chat 字段 |
| 切换/管理 | 弹窗：New Chat 按钮 + Import Chat 按钮 + 搜索框 + 列表（文件名/日期/大小/消息数/预览，每项有重命名/导出 JSONL/导出 TXT/删除按钮） | `POST /api/chats/search`、`/get`、`/rename`、`/delete`、`/recent` |
| 导入 | 文件选择（.json/.jsonl 多选），按格式自动识别（Kobold Lite/CAI Tools/oobabooga/Agnai/RisuAI） | `POST /api/chats/import` |
| 导出 | 列表项按钮：JSONL 原文 / TXT（跳过 is_system 消息拼纯文本） | `POST /api/chats/export` |

## 3. 多用户系统

### 3.1 登录页

| 项 | 规格 |
|---|---|
| UI 形态 | 独立页面（非弹窗），居中卡片：用户卡片列表（头像+用户名+handle，点击选中）或 discreet 模式（隐藏列表，文本输入 handle）+ 密码输入框 + 登录按钮 + 忘记密码链接 |
| 控件 | 用户卡片（可点击）、`input[type=password]`、登录按钮、密码找回块（恢复码 + 新密码输入） |
| 后端 API | `POST /api/users/list`（用户列表）、`POST /api/users/login`（{handle, password}，限流 5 次/分钟/IP）、`POST /api/users/recover-step1/2`（恢复码打印到服务器控制台） |
| 会话 | cookie session + CSRF token；`enableUserAccounts=false` 时跳过登录直接用默认用户 |

### 3.2 管理面板（admin.html）

| 项 | 规格 |
|---|---|
| UI 形态 | 弹窗（非独立页面），顶部两个 tab：Manage Users / New User |
| 用户列表 | 用户卡片：头像（换/删按钮）、锁图标（有无密码）、用户名、handle、Role、Status、Created + 操作按钮组 |
| 操作按钮 | 改名（铅笔）、启用/禁用（对勾/禁止，不能禁用自己）、提升/降级（上下箭头，不能升降自己）、下载备份（zip）、改密（钥匙）、删除（红色垃圾桶） |
| 创建用户表单 | Display Name（text 必填）+ User Handle（text，pattern `[a-z0-9-]+`，输入名字时自动 slugify 填充）+ Password/Confirm（password，可留空）+ Create 按钮 |
| 后端 API | `POST /api/users/get`、`/create`（{handle, name, password, admin}，scrypt 哈希）、`/enable`、`/disable`、`/promote`、`/demote`、`/delete`（{handle, purge}，purge 删除整个数据目录）、`/slugify` |
| 删除确认 | 弹窗：checkbox（同时清除数据）+ 文本输入（输入 handle 确认）+ 红色警告 |

### 3.3 用户资料 / 修改密码

| 项 | 规格 |
|---|---|
| 用户资料弹窗 | 头部（Hi, 用户名 + 改名按钮）+ Account Info（头像/Handle/Role/Created/Password）+ Account Actions（改密/快照/下载备份）+ Danger Zone（Reset Settings 需密码确认 / Reset Everything 两步确认） |

### 9.3 关键设计差异（ST-Zero vs ST）

| 项 | ST | ST-Zero |
|---|---|---|
| prompt 组装 | 前端 | **服务端**（纯函数引擎） |
| 世界书扫描 | 前端 | **服务端** |
| 正则处理 | 前端 | **服务端** |
| 宏替换 | 前端 | **服务端** |
| token 预算 | 前端 | **服务端** |
| 搜索/排序/分页 | 前端本地 | **服务端 SQLite 查询** |
| 设置保存 | 整包 POST | **字段级 API** |
| secrets 存储 | 明文 JSON | **AES-256-GCM 加密** |
| 角色卡保存 | 整表单 multipart | **字段级 PATCH** |
| 实时预览 | 前端重复实现 | **服务端 dry-run API 复用** |
