# ST-Zero 核心算法规格

> 版本：v0.2（已实现）
> 日期：2026-08-30
> 目标：定义"计算后移"核心算法的输入/输出与行为，全部为纯函数，可单元测试
> 权威来源：SillyTavern 源码（参考/SillyTavern/public/scripts/world-info.js、extensions/regex/engine.js、PromptManager.js、openai.js）
> 实现状态：世界书扫描/正则/宏/token 预算已实现并通过单元测试（tests/engine/，37 个测试）；生成链路已接入真实数据（src/server/api/chats.ts）

---

## 1. 设计原则

1. **纯函数**：输入（角色卡+世界书+聊天+设置）→ 输出（prompt），无副作用，可单测
2. **前后端共享**：服务端直接调用；前端通过只读 API（dry-run）复用做实时预览
3. **与 ST 行为一致**：同一输入产生同一输出（对照测试）
4. **确定性**：除显式随机（概率触发、组权重）外，输出确定

## 2. 世界书扫描器（Lorebook Engine）

### 2.1 输入

```ts
interface WorldInfoScanInput {
  entries: WorldInfoEntry[]          // 世界书条目（含全局 + 角色内嵌）
  chatMessages: ChatMessage[]        // 聊天历史（含名字前缀）
  settings: WorldInfoSettings        // 全局设置（深度/预算/递归等）
  character?: CharacterData          // 角色数据（用于 matchCharacter* 匹配）
  persona?: string                   // 用户 persona 描述
  maxContext: number                 // 上下文 token 上限
  isDryRun?: boolean                 // 预览模式（不触发副作用）
}
```

### 2.2 输出

```ts
interface WorldInfoScanResult {
  activatedEntries: WorldInfoEntry[]     // 激活的条目（按插入顺序）
  worldInfoBefore: string                // 角色定义前注入的内容
  worldInfoAfter: string                 // 角色定义后注入的内容
  worldInfoExamples: WorldInfoEntry[]    // 示例区条目（EMTop/EMBottom）
  worldInfoDepth: WorldInfoEntry[]       // 深度条目（atDepth）
  anBefore: WorldInfoEntry[]             // 作者注顶部条目
  anAfter: WorldInfoEntry[]              // 作者注底部条目
  outletEntries: Record<string, WorldInfoEntry[]>  // 命名 outlet 条目
  tokenCount: number                     // 注入内容 token 数
}
```

### 2.3 扫描流程

```
1. 构建扫描缓冲（depthBuffer）
   - 每条消息加 "角色名:" 前缀（settings.world_info_include_names）
   - 消息间用 \x01 分隔
   - 深度上限 MAX_SCAN_DEPTH（ST 为 100）

2. 关键词匹配（对每条 entry）
   - 大小写敏感：entry.caseSensitive ?? settings.world_info_case_sensitive
   - 整词匹配：entry.matchWholeWords ?? settings.world_info_match_whole_words
   - 正则键：/pattern/flags 形式（entry.use_regex 或 keys 以 / 开头）
   - selective 逻辑：
     - AND ANY（0）：keys 任一命中
     - AND ALL（1）：keys 全部命中
     - NOT ANY（2）：keys 任一命中则排除
     - NOT ALL（3）：keys 全部命中则排除
   - selective=true 时需 keys 和 secondary_keys 各命中一个
   - constant=true 直接激活（受预算限制）
   - 概率：useProbability && random(0,100) > probability 则跳过
   - 计时效果：sticky（激活后保持 N 条）、cooldown（冷却 N 条）、delay（至少 N 条后才可激活）

3. 递归扫描（settings.world_info_recursive）
   - 已激活条目的 content 加入递归缓冲
   - 对递归缓冲再次扫描（excludeRecursion 条目不参与）
   - 最大递归步数 world_info_max_recursion_steps
   - preventRecursion 条目激活后停止递归

4. 组评分（settings.world_info_use_group_scoring）
   - 同组条目按 groupWeight 加权随机选择
   - groupOverride 条目优先（组内选 order 最大者）

5. Token 预算裁剪（settings.world_info_budget，默认 25%）
   - 预算 = maxContext * budget / 100
   - 按 priority（默认 = insertion_order）从小到大裁剪
   - ignoreBudget 条目不参与裁剪
   - 裁剪后按 insertion_order 排序

6. 位置分配
   - position 0 (before_char) → worldInfoBefore
   - position 1 (after_char) → worldInfoAfter
   - position 2 (ANTop) / 3 (ANBottom) → anBefore/anAfter
   - position 4 (atDepth) → worldInfoDepth（按 depth 字段）
   - position 5 (EMTop) / 6 (EMBottom) → worldInfoExamples
   - position 7 (outlet) → outletEntries（按 outletName）
```

### 2.4 与 ST 的对照点

- ST 实现：`public/scripts/world-info.js` 的 `WorldInfoBuffer`（matchKeys/getScore）、`checkWorldInfo`、`getWorldInfoPrompt`
- 关键行为：`\x01` 分隔符、`角色名:` 前缀、MAX_SCAN_DEPTH=100、预算默认 25%

## 3. 正则引擎（Regex Engine）

### 3.1 输入

```ts
interface RegexInput {
  text: string
  scripts: RegexScript[]           // 按作用域合并：global + scoped + preset
  placement: RegexPlacement         // 1=USER_INPUT, 2=AI_OUTPUT, 3=SLASH_COMMAND, 5=WORLD_INFO, 6=REASONING
  depth: number                     // 消息深度（0=最后一条）
  isMarkdown: boolean
  isPrompt: boolean
  isEdit: boolean
}
```

### 3.2 输出

```ts
interface RegexResult {
  text: string                      // 处理后的文本
  appliedScripts: string[]          // 实际应用的脚本名（调试用）
}
```

### 3.3 处理流程

```
对每个脚本（按顺序）：
1. 过滤：
   - disabled 跳过
   - markdownOnly && !isMarkdown 跳过
   - promptOnly && !isPrompt 跳过
   - !markdownOnly && !promptOnly && (isMarkdown || isPrompt) 跳过
   - isEdit && !runOnEdit 跳过
   - depth 超出 minDepth/maxDepth 跳过
   - placement 不含当前 placement 跳过

2. 构建正则：
   - substituteRegex=0 (NONE)：findRegex 按字面
   - substituteRegex=1 (RAW)：宏原样替换
   - substituteRegex=2 (ESCAPED)：宏值正则转义

3. 执行替换：
   - replaceString 中 {{match}} → $0（完整匹配）
   - $1/$2 数字捕获组、$<name> 命名捕获组
   - trimStrings 从匹配中移除
   - 最终替换文本再执行宏替换（substituteParams）
```

### 3.4 与 ST 的对照点

- ST 实现：`public/scripts/extensions/regex/engine.js` 的 `getRegexedString`/`runRegexScript`/`filterString`
- 注意：ST 的 `RegexProvider` 缓存编译后的正则

## 4. 宏替换器（Macro Processor）

### 4.1 支持的宏（MVP 子集）

| 宏 | 说明 |
|---|---|
| `{{char}}` | 角色名（V3 有 nickname 时用 nickname） |
| `{{user}}` | 用户显示名 |
| `{{random:A,B,C}}` | 随机选一个 |
| `{{pick:A,B,C}}` | 随机选一个（同 random） |
| `{{roll:N}}` / `{{roll:dN}}` | 随机数 |
| `{{// 注释}}` | 注释（不输出） |
| `{{comment: 文本}}` | 注释 |
| `{{reverse:A}}` | 反转字符串 |
| `{{description}}` | 角色描述 |
| `{{personality}}` | 角色人格 |
| `{{scenario}}` | 角色场景 |
| `{{persona}}` | 用户 persona |
| `{{wiBefore}}` / `{{wiAfter}}` | 世界书注入内容 |
| `{{system}}` | 系统提示词 |
| `{{outlet::Name}}` | 命名 outlet 内容 |
| `{{trim}}` | 上下文模板中的裁剪标记 |

### 4.2 替换规则

- 大小写不敏感（`{{CHAR}}` 等同 `{{char}}`）
- 嵌套宏：先内后外
- 未识别宏：原样保留（不报错）
- 宏值中的特殊字符：按上下文转义（正则上下文用 ESCAPED 模式）

### 4.3 与 ST 的对照点

- ST 实现：`public/scripts/macros.js` 的 `substituteParams`/`substituteParamsExtended`
- MVP 只做子集，完整宏清单后置（STscript 阶段）

## 5. Prompt 组装器（Prompt Builder）

### 5.1 输入

```ts
interface PromptBuildInput {
  character: CharacterData
  chat: ChatMessage[]
  worldInfo: WorldInfoScanResult
  persona: string
  preset: Preset                    // 上下文预设 + 指令预设 + 采样预设
  settings: GenerationSettings
  mode: 'chat' | 'text'             // Chat Completion 或 Text Completion
}
```

### 5.2 输出

```ts
interface PromptBuildResult {
  messages: ChatCompletionMessage[]  // Chat Completion 模式
  prompt: string                     // Text Completion 模式
  tokenCount: number
  budget: { used: number, total: number }
}
```

### 5.3 Chat Completion 组装流程

```
1. 按 prompt_order 排序提示词块（identifier 顺序）
2. 组装各块：
   - main：主提示词（system_prompt 或预设 main）
   - worldInfoBefore/worldInfoAfter：世界书注入
   - personaDescription：用户 persona
   - charDescription/charPersonality/scenario：角色定义
   - dialogueExamples：示例对话（<START> 分隔）
   - chatHistory：聊天历史（消息数组）
   - jailbreak/nsfw：可选块
3. 宏替换（每块内容）
4. 正则处理（promptOnly 脚本，按块位置）
5. Token 预算管理：
   - 总预算 = openai_max_context
   - 固定块（main/角色定义/世界书）优先
   - 聊天历史从旧到新裁剪（保留最近消息）
   - 溢出时裁剪示例对话 → 聊天历史
6. 输出消息数组
```

### 5.4 Text Completion 组装流程

```
1. 用上下文预设的 story_string 模板（Handlebars）
2. 填充变量：{{system}}/{{description}}/{{personality}}/{{scenario}}/{{wiBefore}}/{{wiAfter}}/{{persona}}/{{trim}}
3. 用指令预设包装：
   - input_sequence/output_sequence/system_sequence
   - 消息间插入序列标记
   - stop_sequence 作为停止字符串
4. 宏替换 + 正则处理
5. Token 预算管理（同上）
6. 输出单字符串
```

### 5.5 与 ST 的对照点

- ST 实现：`public/scripts/openai.js`（prepareOpenAIMessages/populateChatCompletion/populateChatHistory）、`public/scripts/PromptManager.js`、`public/scripts/chat-templates.js`
- 默认 prompt 顺序：main → worldInfoBefore → personaDescription → charDescription → charPersonality → scenario → enhanceDefinitions → nsfw → worldInfoAfter → dialogueExamples → chatHistory → jailbreak

## 6. Token 预算管理器（Token Budget）

### 6.1 输入

```ts
interface BudgetInput {
  blocks: PromptBlock[]              // 各提示词块（含优先级）
  maxContext: number                 // 上下文上限
  tokenizer: (text: string) => number  // token 计数函数
}
```

### 6.2 算法

```
1. 计算各块 token 数
2. 固定块（priority=high）：main、角色定义、世界书、persona → 全部保留
3. 弹性块（priority=low）：示例对话、聊天历史 → 按优先级裁剪
4. 聊天历史裁剪：从最旧消息开始丢弃，直到总 token ≤ maxContext
5. 世界书预算：maxContext * world_info_budget / 100（扫描器内处理）
6. 输出：保留的块 + 总 token 数
```

### 6.3 与 ST 的对照点

- ST 实现：`public/scripts/openai.js` 的 `ChatCompletion` 类（setTokenBudget/canAfford/reserveBudget）

## 7. Token 计数器（Tokenizer）

### 7.1 接口

```ts
// 服务端端点
POST /api/tokenizers/count
{ "text": string, "model": string }  →  { "count": number }

POST /api/tokenizers/encode
{ "text": string, "model": string }  →  { "tokens": number[] }
```

### 7.2 实现

- 优先：模型对应 tokenizer（tiktoken / sentencepiece / web-tokenizers）
- 兜底：字节估算（BYTES_PER_TOKEN = 3.35，ST 同款）
- 缓存：LRU 缓存（文本 → token 数）

### 7.3 与 ST 的对照点

- ST 实现：`src/endpoints/tokenizers.js`（已后移，直接借鉴）
