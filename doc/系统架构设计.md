## 1. 架构总览

```
┌─────────────────────────────────────────────────────────┐
│                       浏览器 (Svelte 5 SPA)              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐   │
│  │ 角色卡UI │ │ 聊天UI   │ │ 世界书UI │ │ 管理面板 │   │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘   │
│  状态管理 (Svelte stores) · i18n · 主题 · 路由          │
└───────────────┬─────────────────────────────────────────┘
                │ REST API (JSON) + SSE (流式)
┌───────────────▼─────────────────────────────────────────┐
│              Node.js 服务端 (Express/Hono)               │
│  ┌──────────────────────────────────────────────────┐  │
│  │ 认证层: JWT · requireAuth · requireAdmin          │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ 计算引擎（核心，全部后移）                          │  │
│  │  · 世界书扫描器 (lorebook-engine)                 │  │
│  │  · 正则引擎 (regex-engine)                        │  │
│  │  · Prompt 组装器 (prompt-builder)                 │  │
│  │  · 宏替换器 (macro-processor)                     │  │
│  │  · Token 预算管理器 (token-budget)                │  │
│  │  · Token 计数器 (tokenizer)                       │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ 格式兼容层 (format-layer)                          │  │
│  │  · 角色卡解析/导出 (PNG tEXt / JSON / CharX)      │  │
│  │  · 世界书解析 (ST JSON)                           │  │
│  │  · 正则解析 (ST JSON)                             │  │
│  │  · 聊天 JSONL 读写                                │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ 数据层: SQLite (元数据) + 文件系统 (角色卡/图片)     │  │
│  ├──────────────────────────────────────────────────┤  │
│  │ 后端适配器: OpenAI 兼容 · KoboldAI                 │  │
│  └──────────────────────────────────────────────────┘  │
└───────────────┬─────────────────────────────────────────┘
                │
        ┌───────▼────────┐   ┌──────────────────┐
        │  SQLite 数据库  │   │  data/ 文件系统   │
        │  (users/chats/ │   │  (角色卡PNG/图片/  │
        │   settings)    │   │   世界书JSON)     │
        └────────────────┘   └──────────────────┘
```

**核心设计原则**：

1. **计算后移**：世界书扫描、正则、prompt 构建、宏替换、token 预算全部在服务端执行。前端只做渲染、交互、流式展示
2. **纯函数核心**：计算引擎设计为纯函数（输入：角色卡+世界书+聊天+设置 → 输出：prompt），可单元测试，前后端可共享同一实现（服务端直接跑，浏览器端复用做实时预览）
3. **格式兼容层独立**：所有 ST 格式的读写集中在一个模块层，输入输出与 ST 1:1 兼容
4. **单容器部署**：一个 Node 进程服务一切（静态文件 + REST API + SSE + WebSocket），SQLite + 文件系统持久化

## 2. 技术选型（ADR）

### ADR-001：前端框架 — Svelte 5 + TypeScript + Vite

**决策**：Svelte 5（runes）+ TypeScript + Vite

**理由**：
- 生态内参考最多：RisuAI（Svelte 5）、ChungusHub（Svelte 5）都是 ST 生态的现代重写，架构文档可直接参考
- 编译期优化，运行时无虚拟 DOM 开销，bundle 体积小（满足 ≤500KB gzip 目标）
- Svelte 5 runes 的细粒度响应式适合聊天流式更新的高频状态变更
- 单文件组件（.svelte）适合角色卡编辑器、世界书编辑器这类复杂表单 UI

**备选**：React 18 + Vite（LibreChat 路线）——生态更大但 bundle 更大；Vue 3——生态内无参考

### ADR-002：后端框架 — Node.js + Express（或 Hono）

**决策**：Node.js ≥ 20 + Express 5（起步），预留 Hono 迁移路径

**理由**：
- 与 ST 生态一致（ST 用 Express），中间件生态成熟
- LibreChat 用 Express 5 验证了大规模 AI 应用可行性
- Hono 作为备选：RisuAI 正在迁移到 Hono（支持 Bun/Node/CF Workers），若未来需要多平台部署可迁移

### ADR-003：数据库 — SQLite（better-sqlite3）+ 文件系统混合

**决策**：结构化数据（用户、聊天元数据、设置）用 SQLite；文件型数据（角色卡 PNG、背景图、世界书 JSON）用文件系统

**理由**：
- 单容器部署最简单（无需 MongoDB/PostgreSQL 独立服务）
- 角色扮演应用天然文件多（角色卡图片），ST 的文件目录模式（每用户目录树）直接借鉴
- SQLite 支持 WAL 模式，单机并发足够（家庭/小团体场景）
- 数据备份 = 复制数据卷，简单可靠

**备选**：MongoDB（LibreChat/Agnaistic）——多租户场景才需要；纯文件系统（ST）——查询能力弱

### ADR-004：认证 — JWT + bcrypt

**决策**：JWT access token（15 分钟过期）+ bcrypt 密码哈希；JWT payload 携带 `{userId, username, role, ver}`

**理由**：
- 无状态，适合 Docker 多实例部署
- `ver` claim 借鉴 ST 的"版本哈希"思路：密码/角色变更后递增版本号，旧 token 自动失效
- 登录限流（rate-limiter-flexible，5 次/分钟/IP）借鉴 ST

**备选**：cookie session（ST）——单机简单但多实例需共享存储

### ADR-005：角色模型 — 单 role 字段 + admin 超集语义

**决策**：`role: 'user' | 'admin'`（预留 `'pending'`），admin 是 user 的超集

**理由**：
- 完全符合需求"管理员可当普通用户使用，只是多一个管理面板入口"
- Open WebUI 验证的模式：`role === 'admin' || hasPermission(...)`，admin 绕过所有权限检查
- 权限检查两级：粗粒度 role 守卫（中间件）+ 细粒度权限字典（预留，初期只做粗粒度）

### ADR-006：管理面板 — 同应用内路由 + 条件渲染入口

**决策**：前端 `/admin` 路由 + 侧边栏 `{#if role === 'admin'}` 条件渲染入口；后端 `/api/admin/*` 挂 `requireAdmin` 中间件

**理由**：
- Open WebUI 最佳实践，与需求完全一致
- 双保险：前端路由守卫（非 admin 重定向）+ 后端中间件（403）
- 反面案例：LibreChat 独立管理端（ADMIN_PANEL_URL）——管理功能庞大时才需要

### ADR-007：流式传输 — SSE

**决策**：SSE（Server-Sent Events）用于 LLM 流式输出

**理由**：
- 实现简单、兼容性好、自动重连
- 单向流（服务端→客户端）足够 LLM 流式场景
- WebSocket 预留：未来需要双向通信（协作、实时同步）时引入

### ADR-008：状态管理 — Svelte stores（原生）

**决策**：Svelte 5 runes（$state/$derived/$props）+ 模块级 store

**理由**：
- Svelte 原生响应式，无需额外状态库
- 聊天会话状态用 runes 管理流式增量更新
- 若未来迁移 React 则用 Zustand（LobeChat 验证）

### ADR-009：数据隔离 — 混合方案

**决策**：
- 结构化数据（用户、聊天、设置）：SQLite 表带 `user_id` 字段 + 复合索引
- 文件数据（角色卡 PNG、背景图、世界书）：每用户目录 `data/users/{userId}/...` + 路径穿越防护（`isPathUnderParent` 模式）

**理由**：
- 角色扮演应用文件多，ST 的目录模板（约 40 个子目录）直接借鉴
- 结构化数据用数据库查询过滤（Open WebUI/LibreChat 模式）
- 单用户模式：`data/users/default-user/` 与多用户模式目录结构一致，平滑过渡

### ADR-010：单用户/多用户模式切换

**决策**：`ENABLE_ACCOUNTS` 环境变量（默认 false）

**理由**：
- ST 模式最优雅：关闭时内置 DEFAULT_USER（admin）直接使用；开启时走登录
- 单用户模式数据目录 = `default-user`，开启多用户后该用户数据自动成为第一个用户的数据
- 首个用户自动成为 admin（Open WebUI 模式）

## 4. 数据模型

### 4.1 SQLite 表

```sql
-- 用户
CREATE TABLE users (
  id TEXT PRIMARY KEY,              -- uuid
  username TEXT UNIQUE NOT NULL,    -- 登录名
  password_hash TEXT NOT NULL,      -- bcrypt
  role TEXT NOT NULL DEFAULT 'user',-- 'user' | 'admin' | 'pending'
  enabled INTEGER NOT NULL DEFAULT 1,
  display_name TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL,
  ver INTEGER NOT NULL DEFAULT 0    -- 版本号（密码/角色变更时递增，使旧 JWT 失效）
);

-- 角色卡元数据（PNG 文件存文件系统，元数据存 DB 便于搜索）
CREATE TABLE characters (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,
  avatar_path TEXT NOT NULL,        -- 相对路径（每用户目录内）
  spec TEXT NOT NULL,               -- 'chara_card_v2' | 'chara_card_v3'
  tags TEXT,                        -- JSON 数组
  fav INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX idx_characters_user ON characters(user_id, updated_at);

-- 聊天会话
CREATE TABLE chats (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  character_id TEXT NOT NULL REFERENCES characters(id),
  title TEXT,
  file_path TEXT NOT NULL,          -- JSONL 文件相对路径
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX idx_chats_user ON chats(user_id, updated_at);

-- 世界书
CREATE TABLE worlds (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id),
  name TEXT NOT NULL,
  file_path TEXT NOT NULL,          -- JSON 文件相对路径
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX idx_worlds_user ON worlds(user_id);

-- 设置（每用户 JSON）
CREATE TABLE settings (
  user_id TEXT PRIMARY KEY REFERENCES users(id),
  data TEXT NOT NULL                -- JSON（含正则、预设引用、UI 偏好）
);

-- 站点设置（全局）
CREATE TABLE site_settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

### 4.2 文件系统布局

data/

    └── {userId}/              # 单用户模式为 default-user

        ├── avatars/           # 用户头像

## 6. 计算后移设计（核心）

### 6.1 生成流程（服务端）

```
用户点击发送
  → POST /api/chats/:id/messages {content}
  → 服务端：
    1. 加载角色卡 + 世界书 + 聊天历史 + 设置
    2. 宏替换（{{char}}/{{user}}/{{random}} 等）
    3. 世界书扫描（关键词匹配 → 递归扫描 → token 预算裁剪）
    4. 正则处理（用户输入 → 世界书内容 → prompt 各段）
    5. Prompt 组装（Chat Completion 消息数组 或 Text Completion 字符串）
    6. Token 预算管理（上下文裁剪）
    7. 调用后端适配器（OpenAI/KoboldAI）
    8. SSE 流式返回
    9. 保存消息到 JSONL
```

### 6.2 实时预览（前端复用）

- 前端"token 计数"、"世界书激活预览"等实时展示通过调用服务端只读接口实现（`POST /api/preview/prompt`，dry-run 模式）
- 计算引擎为纯函数，服务端直接调用；前端不重复实现算法

### 6.3 纯函数接口定义

```ts
// 世界书扫描
function scanWorldInfo(
  input: {
    entries: WorldInfoEntry[],
    chatMessages: ChatMessage[],
    settings: WorldInfoSettings,
    character?: CharacterData,
    persona?: string,
  }
): {
  activatedEntries: WorldInfoEntry[],
  worldInfoBefore: string,
  worldInfoAfter: string,
}

// 正则处理
function applyRegex(
  input: {
    text: string,
    scripts: RegexScript[],
    placement: RegexPlacement,
    depth: number,
    isMarkdown: boolean,
    isPrompt: boolean,
  }
): string

// Prompt 组装
function buildPrompt(
  input: {
    character: CharacterData,
    chat: ChatMessage[],
    worldInfo: WorldInfoResult,
    persona: string,
    preset: Preset,
    settings: GenerationSettings,
  }
): {
  messages: ChatCompletionMessage[],  // Chat Completion 模式
  prompt: string,                       // Text Completion 模式
  tokenCount: number,
}
```

## 8. 安全设计

- 密码 bcrypt 哈希（cost 12）
- JWT 签名 + `ver` claim（密码/角色变更后旧 token 失效）
- 登录限流：5 次/分钟/IP
- API key 加密存储（AES-256-GCM，密钥来自 JWT_SECRET 派生）
- 文件路径穿越防护：所有文件访问经 `isPathUnderParent` 校验
- 管理端点全部 `requireAdmin` 中间件
- 前端 `/admin` 路由守卫（非 admin 重定向）
- Docker 默认非 root 运行（可选 PUID/PGID）
