# ST-Zero 项目调研报告

> 调研日期：2026-08-30
> 目标：从零重置一个类酒馆（SillyTavern）项目，适配其庞大社区生态（角色卡、正则、世界书等可分享资源），Web 平台、Docker 部署，解决原版三大痛点：UI 落后、运行臃肿、计算全在前端。
> 项目进展：调研结论已全部落地实现（P0/P1 功能完成，68 个测试通过），详见 PRD.md §5.5 实现状态表

## 一、SillyTavern 现状分析（痛点确认）

### 1.1 技术栈

| 层 | 技术 |
|---|---|
| 前端 | **jQuery 3.5.1 + 原生 JS**（无 Vue/React/Svelte，无 TypeScript），Webpack 仅打包 lib.js，主应用以 `<script>` 标签直接加载 |
| 后端 | Node.js ≥ 20 + Express，**无数据库**，全部文件系统存储（`data/` 目录） |
| 服务端 ML | Transformers.js fork（ONNX WASM）：文本分类、图像描述、embedding、whisper、TTS |
| 服务端 tokenizer | sentencepiece-js / web-tokenizers / tiktoken |
| 构建 | Webpack（仅 lib.js 入口） |

### 1.2 前端"臃肿"的直接证据

| 文件 | 大小 |
|---|---|
| `public/script.js` | **495 KB**（单文件） |
| `public/scripts/openai.js` | 299 KB |
| `public/scripts/slash-commands.js` | 294 KB |
| `public/scripts/world-info.js` | 260 KB |
| `public/scripts/power-user.js` | 172 KB |

- `public/scripts/` 共 **75 个 JS 文件 + 6 个子目录**，全部浏览器端原生加载
- 前端 JS 总量约 **11.5 MB**（scripts 8.8M + lib 2.7M），202 个文件
- CSS：`style.css` 6456 行 + `css/` 376K
- 捆绑 jQuery 全家桶：jquery-ui、jquery-cropper、jquery.transit、jquery.ui.touch-punch 等

### 1.3 计算逻辑分布（"计算后移"的关键依据）

**目前在前端（浏览器）执行的计算 —— 重写时应后移的部分：**

| 计算 | 位置 |
|---|---|
| **Prompt 构建**（Chat Completion 消息数组组装） | 前端 `openai.js` 的 `prepareOpenAIMessages`/`populateChatCompletion`，`PromptManager.js` |
| **世界书扫描/匹配/激活** | 前端 `world-info.js` 的 `WorldInfoBuffer`（`matchKeys`/`getScore`）、`checkWorldInfo`、`getWorldInfoPrompt` |
| **正则处理** | 前端 `extensions/regex/engine.js`（`getRegexedString`/`runRegexScript`） |
| **宏替换**（`{{char}}`/`{{user}}`/`{{random}}` 等） | 前端 `macros.js`，`substituteParams` |
| **STscript 执行** | 前端 `slash-commands.js`（294 KB） |
| **上下文预算管理**（token budget 分配） | 前端 `openai.js` 的 `ChatCompletion` 类 |
| **群聊逻辑** | 前端 `group-chats.js` |

**已经在服务端（Node）执行的计算 —— 可借鉴的"后移"先例：**

| 计算 | 位置 |
|---|---|
| **Token 计数** | 服务端 `src/endpoints/tokenizers.js`（`/api/tokenizers/{llama,mistral,claude,...}/count`） |
| **Embedding 生成**（本地模式） | 服务端 `src/transformers.js` + `vectors.js` |
| **文本分类/图像描述/whisper/TTS** | 服务端 `src/transformers.js` 管线 |
| **角色卡 PNG 解析/写入** | 服务端 `src/character-card-parser.js`、`src/png/` |
| **文件存储/备份/搜索** | 服务端各 endpoints 模块 |

**结论**：token 计数已后移，说明官方认可服务端计算路线；但世界书、正则、prompt 构建、宏替换、STscript 仍全在前端——这是浏览器卡顿和移动端体验差的根源。

### 1.4 架构

- 前端 `public/` + 后端 `src/`（server-main.js 入口、endpoints/ 约 40 个路由模块、backends/ 适配器）
- 数据目录 `data/{userHandle}/` 共 31 个子目录：characters/、chats/、groups/、worlds/、backgrounds/、预设目录、QuickReplies/、vectors/ 等
- 扩展系统双轨制：UI 扩展（manifest.json + 动态注入）+ 服务端插件（PluginModule 接口 + `/api/plugins/{id}` 路由）
- 多后端：本地（KoboldCpp/llama.cpp/Ollama/Oobabooga/TabbyAPI）+ 云端（OpenAI/Claude/Google/OpenRouter/DeepSeek/NovelAI 等 20+）
- 两种 prompt 结构：Chat Completion（消息数组）和 Text Completion（单字符串 + Instruct 模板）
- Docker：`ghcr.io/sillytavern/sillytavern`，端口 8000，卷挂载 config/data/plugins/extensions，heartbeat 健康检查

## 二、资源格式规范（兼容性生命线）

> 社区存量数据（Chub 上数十万卡片）依赖这些格式，必须 1:1 兼容。

### 2.1 角色卡 V2（`malfoyslastname/character-card-spec-v2`）

```ts
type TavernCardV2 = {
  spec: 'chara_card_v2'
  spec_version: '2.0'
  data: {
    name, description, personality, scenario, first_mes, mes_example: string
    creator_notes: string        // 永不进入提示词
    system_prompt: string        // 空时回退用户全局设置
    post_history_instructions: string
    alternate_greetings: string[]
    character_book?: CharacterBook
    tags: string[]
    creator: string
    character_version: string
    extensions: Record<string, any>  // 未知 key 不得销毁
  }
}
```

- **PNG 嵌入**：JSON 字符串 base64 编码存入 PNG **tEXt chunk，key 为 `chara`**（V1 用 `chardata`）
- 版本检测：`spec === undefined` 为 V1；`spec === 'chara_card_v2'` 读 `data` 下字段
- CharacterBook（内嵌世界书）：`{ name, description, scan_depth, token_budget, recursive_scanning, extensions, entries[] }`；entry 含 `keys`、`content`、`enabled`、`insertion_order`、`selective`、`secondary_keys`、`constant`、`position`（before_char/after_char）等

### 2.2 角色卡 V3（`kwaroran/character-card-spec-v3`，提案状态）

- **PNG chunk key 改为 `ccv3`**（与 `chara` 并存时优先 `ccv3`）
- 新增字段：`assets`（`[{type, uri, name, ext}]`）、`nickname`、`creator_notes_multilingual`、`source`、`group_only_greetings`、`creation_date`、`modification_date`
- 世界书条目新增 `use_regex`（必填）、`constant`（必填实现），content 支持装饰器 `@@depth`、`@@role`、`@@position`
- 新增 **CHARX zip 格式**（card.json + `embeded://` 资源）；独立世界书导出 `{ spec: 'lorebook_v3', data: Lorebook }`
- 注意：V3 仍是提案，SillyTavern 当前主要读写 V2，但已支持导入 V3

### 2.3 世界书（World Info / Lorebook）

- 文件：`worlds/{name}.json`，结构 `{ name?, entries: {...}, extensions? }`
- **关键：`entries` 是以 uid 为键的对象（不是数组）**，每个条目带 `uid` 字段
- 条目字段（内部 camelCase → 存储 snake_case 映射）：
  - `key`→`keys`、`keysecondary`→`secondary_keys`、`order`→`insertion_order`（默认 100）
  - `position`→`extensions.position`（0=before_char, 1=after_char, 2=ANTop, 3=ANBottom, 4=atDepth, 5=EMTop, 6=EMBottom, 7=outlet）
  - `disable`→`enabled`（取反）、`constant`、`selective`、`selectiveLogic`（0=AND ANY, 1=AND ALL, 2=NOT ANY, 3=NOT ALL）
  - `probability`→`extensions.probability`（默认 100）、`useProbability`→`extensions.use_probability`
  - `depth`→`extensions.depth`（默认 4）、`scanDepth`→`extensions.scan_depth`
  - `group`→`extensions.group`、`groupOverride`、`groupWeight`（默认 100）
  - `automationId`→`extensions.automation_id`、`role`→`extensions.role`（0=system, 1=user, 2=assistant）
  - `sticky`/`cooldown`/`delay`（计时效果）、`ignoreBudget`→`extensions.ignore_budget`
  - `matchPersonaDescription`/`matchCharacterDescription`/`matchScenario` 等匹配目标
- 全局设置（settings.json）：`world_info_depth`（默认 2）、`world_info_budget`（默认 25%）、`world_info_recursive`、`world_info_case_sensitive`、`world_info_match_whole_words` 等
- 扫描缓冲：ST 给每条消息加 `角色名:` 前缀，v1.12.6 起用 `\x01` 字符分隔

### 2.4 正则（Regex）脚本

```json
{
  "id": "UUID", "scriptName": "脚本名",
  "findRegex": "/pattern/flags", "replaceString": "支持 {{match}}、$1 捕获组",
  "trimStrings": [], "placement": [1, 2],
  "disabled": false, "markdownOnly": false, "promptOnly": false,
  "runOnEdit": false, "substituteRegex": 0, "minDepth": null, "maxDepth": null
}
```

- `placement` 枚举：0=MD_DISPLAY（废弃）、1=USER_INPUT、2=AI_OUTPUT、3=SLASH_COMMAND、4=sendAs、5=WORLD_INFO、6=REASONING
- 三种作用域：global（settings.json 的 `extension_settings.regex`）、scoped（角色卡 `extensions.regex_scripts`）、preset（AI 预设文件）

### 2.5 预设（Preset）

- 按 API 类型分目录：`OpenAI Settings/`、`KoboldAI Settings/`、`NovelAI Settings/`、`TextGen Settings/`、`instruct/`、`context/`、`sysprompt/`、`reasoning/`
- 采样器预设：`temp`、`rep_pen`、`rep_pen_range`、`top_p`、`min_p`、`top_a`、`top_k`、`typical`、`tfs`、`rep_pen_slope`、`sampler_order`（索引固定语义：0=top_k, 1=top_a, 2=typical, 3=top_p, 4=min_p, 5=tfs, 6=temp）
- 指令预设：`input_sequence`、`output_sequence`、`system_sequence`、`stop_sequence`、`wrap`、`macro`、`names_behavior`（force/auto/none）等（**无 `enabled` 字段**，运行时开关在 settings）
- 上下文预设：`story_string` 是 Handlebars 模板（`{{system}}`、`{{description}}`、`{{wiBefore}}`、`{{wiAfter}}`、`{{persona}}`、`{{trim}}` 等）
- Chat Completion 预设：`prompts` 数组（identifier：main/nsfw/jailbreak/dialogueExamples/chatHistory/worldInfoBefore/worldInfoAfter/charDescription/charPersonality/scenario/personaDescription/enhanceDefinitions）+ `prompt_order`（按 character_id：100000=默认角色，100001=群聊）

### 2.6 聊天记录（JSONL）

- 路径：`chats/{角色名}/{聊天名}.jsonl`（角色名 = avatar_url 去 `.png`）；群聊在 `group chats/{id}.jsonl`
- **首行是 header**：`{ "chat_metadata": {}, "user_name": "unused", "character_name": "unused" }`
- 消息字段：`name`、`is_user`、`send_date`（ISO 时间戳）、`mes`、`extra`（自由扩展区：`api`、`model`、`token_count`、`display_text`、`files` 等）、`swipes`（备选数组）、`swipe_id`、`is_system`
- 校验规则：一行含 `name` 或 `character_name` 或 `chat_metadata` 即视为有效

### 2.7 群聊 / 快捷回复

- Group：`{ id, name, members[], disabled_members[], chat_id, chats[], generation_mode, activation_strategy, auto_mode_delay, allow_self_responses, fav }`
- QuickReplySet：`{ version: 2, name, disableSend, placeBeforeInput, injectInput, color, qrList[], idIndex }`；QuickReply 含 `message`（STscript 命令）、`automationId`（与世界书条目联动）、`executeOnStartup/executeOnUser/executeOnAi` 等触发条件

### 2.8 兼容性关键要点

1. V2 卡片：`{spec, spec_version, data}` 三层结构；PNG 用 `chara` tEXt chunk（base64(utf-8 JSON)）
2. V3 卡片：`ccv3` tEXt chunk 优先于 `chara`；CHARX = zip + card.json + `embeded://` 资源
3. 世界书：`entries` 是 **uid 键控对象**（非数组）；ST 专有字段藏在 `extensions.*` 下；`enabled` 与内部 `disable` 取反
4. 正则：`placement` 是数字数组；scoped 脚本存于 `extensions.regex_scripts`
5. 预设：instruct 预设无 `enabled` 字段；`sampler_order` 索引有固定语义
6. 聊天：JSONL，首行头部含 `chat_metadata`；消息 `extra` 是自由扩展区
7. **兼容原则：所有格式的未知字段必须保留不销毁**（spec 的 MUST NOT destroy 原则）

## 三、角色扮演平台调研

### 3.1 RisuAI（最值得参考之一）

- **GitHub**：kwaroran/RisuAI（1,639 stars，GPL-3.0，活跃维护）
- **技术栈**：Svelte 5 + TypeScript + Vite 8 + Tailwind CSS 4；桌面端 Tauri 2.5；服务端 Node Express（正在用 Hono 重写，支持 Bun/Node/CF Workers）
- **架构**：前端 Svelte SPA + 可选本地 Node 服务端；数据层 localforage（IndexedDB）
- **ST 生态兼容性：高**：角色卡 V1/V2/V3（`@risuai/ccardlib` 库）、CharX、世界书字段与 ST 一致、正则脚本字段与 ST 一致、作者注、`<START>` 分隔符、`{{char}}` 宏
- **Docker**：官方支持（ghcr.io/kwaroran/risuai:latest，端口 6001）
- **注意**：作者已启动 RisuAI-Next（从零重写，Svelte 5 + runes，闭源开发中）——原版单一大状态对象架构已到瓶颈，这是重要教训

### 3.2 Agnaistic（AgnAI）

- **GitHub**：agnaistic/agnai（776 stars，AGPL-3.0）
- **技术栈**：TypeScript 全栈，前端 SolidJS + TailwindCSS，后端 Node Express，MongoDB + Redis（均可选，无 DB 时访客模式）
- **ST 兼容性：中高**：支持导入 tavern/tavernV2/ooba/charas 格式、character_book、alternate_greetings、system_prompt、depth_prompt；**不支持** ST 正则脚本和聊天记录导入
- **价值**：唯一的多用户/多租户架构参考（MongoDB+Redis）

### 3.3 TavernAI（ST 前身）

- TavernAI-v1（2,701 stars，MIT）：ST 于 2023 年 2 月从 TavernAI 1.2.8 fork 而来
- TavernAI 2（2025 年重启）：分支剧情、MultiChat、结构化 Prompt Manager、本地 GGUF 加载；**不兼容** ST 插件生态

### 3.4 KoboldCpp（本地推理层）

- 11,570 stars，C++，基于 llama.cpp，非常活跃
- **KoboldAI API 兼容**（ST 默认本地后端协议）+ OpenAI 兼容 API + Ollama API
- 新应用应至少兼容 KoboldAI API 和 OpenAI API 两种协议

### 3.5 ChungusHub（强烈推荐参考 ★★★）

- **GitHub**：patcireamo/ChungusHub（36 stars，AGPL-3.0，非常活跃）
- **定位**：local-first、隐私优先的 LLM 角色扮演前端，**明确以 SillyTavern 格式兼容为核心卖点**
- **技术栈**：Svelte 5 + Bun + Vite，桌面端（无 Docker）
- **架构亮点**：`architecture/` 目录有 **19 份深度架构文档**（调研中文档质量最高）：
  - `sillytavern-interchange.md`：ST 格式边界完整记录（PNG tEXt/iTXt chunk、CRC-32、角色卡 V1/V2/V3 映射、世界书双形态解析、聊天 .jsonl 导入、正则脚本导入、文件夹级整体迁移）
  - `prompt-pipeline.md`：提示词组装管线（预设驱动、宏系统、lorebook 深度插入、正则作用域、token 预算裁剪）
  - 设计原则：**"字段名保持 SillyTavern 原样"**、解析器 fail-loud、往返不变量（导出→导入固定点）
- **架构**：单 Bun 进程（server/index.ts）做一切：SvelteKit PWA + REST API（/api/*）+ 文件服务（/files/*）+ WebSocket（/ws，流式 token/同步）；**客户端不直接碰文件系统或 SQLite，所有持久化字节流经此进程**——这正是"计算后移"的参考架构
- **局限**：不读 ST 预设、聊天只进不出、正则只读不写

### 3.6 其他

- **Venus AI**：闭源，Chub 官方前端，已并入 chub.ai
- **星野/猫箱**：闭源商业产品，无公开技术资料，仅参考产品形态（语音、表情立绘、UGC 社区）

4. 许可注意：Open WebUI 与 LobeChat 为自定义许可（含使用限制），**闭源商业化应选 MIT 的 LibreChat/NextChat 作参考**；KoboldCpp 与 text-generation-webui 为 AGPL-3.0（仅可参考设计不可复制代码）

## 六、ST-Zero 项目建议

### 6.1 核心定位

- **格式兼容是生命线**：角色卡 PNG tEXt chunk（`chara`/`ccv3`）、JSONL 聊天、世界书 JSON、正则 JSON、预设 JSON 五类格式 1:1 兼容
- **计算后移**：世界书扫描、正则处理、prompt 构建、宏替换、token 预算管理全部迁移到服务端，前端只保留渲染和交互
- **现代 UI**：放弃 jQuery，采用现代框架（Svelte 5 或 React + Vite），组件化、响应式、移动端友好

### 6.2 推荐技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | **Svelte 5 + TypeScript + Vite** | 与 RisuAI/ChungusHub 一致，生态内参考最多；编译期优化、包体小 |
| 后端 | **Node.js + Express（或 Hono）** | 与 ST 生态一致；Hono 支持 Bun/Node/CF Workers 多平台 |
| 数据库 | SQLite（或文件系统兼容层） | 单容器部署简单；需保留 ST 文件格式兼容 |
| 流式 | SSE（+ WebSocket 可选） | 主流方案，实现简单 |
| 状态管理 | Zustand（React）或 Svelte stores | 聊天类应用事实标准 |
| 部署 | Docker 单容器 + 数据卷 | Open WebUI 模式 |

### 6.3 架构设计要点

1. **纯函数 prompt 组装器**：输入（角色卡+世界书+聊天+设置）→ 输出（prompt），Node 端直接跑，浏览器端可复用同一逻辑做实时预览（ChungusHub 的 prompt-assembly.ts 模式）
2. **服务端计算服务层**：token 计数（已有先例）、世界书扫描、正则引擎、宏替换、STscript 执行全部后移
3. **格式兼容层**：PNG tEXt chunk 读写（CRC-32）、角色卡 V1/V2/V3 解析、世界书双形态（character_book vs 原生）、聊天 JSONL 导入导出——参考 ChungusHub 的 sillytavern-interchange.md
4. **扩展系统**：保留 UI 扩展 + 服务端插件双轨制，但简化
5. **多后端抽象**：OpenAI 兼容 API 为统一抽象 + KoboldAI API 兼容

### 6.4 开发路线建议

1. **Phase 1**：格式兼容层（角色卡解析/导出、世界书、正则、聊天 JSONL）+ 基础聊天 UI
2. **Phase 2**：服务端计算引擎（世界书扫描、正则、prompt 构建、token 预算）
3. **Phase 3**：多后端接入（OpenAI 兼容 + KoboldAI）、流式输出
4. **Phase 4**：群聊、快捷回复、STscript 兼容、扩展系统
5. **Phase 5**：Docker 部署、多用户、RAG、TTS/STT、图片生成
